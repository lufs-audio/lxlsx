# Unit 05 — Synthetic fixture DB + golden parity tests

## Objective
Create a checked-in synthetic `finance.db` fixture (v2 schema) plus pytest-style Rust tests
that prove `render_snapshot` output matches the golden six-block structure.

## Context
The golden `finances_2026-08-31.zip` is Daniel's private data — we do **not** commit it.
Instead we build a deterministic synthetic DB whose *shape* mirrors the golden (same six
tables, same category set incl. LIVING/SUBSCRIPTIONS/CREDIT/DINING/PERSONAL/ENTERTAINMENT,
same account names/descriptions), so the structural verifier and renderer are exercised
exactly as they will be against the real DB. `data/` is gitignored; the fixture lives at
`tests/fixtures/finance.db` (a committed binary) or is regenerated by a build script.

## Acceptance criteria
- [ ] `tests/fixtures/seed.sql` (or a `build_fixture.rs`) creates a v2-schema `finance.db` covering all six blocks with non-empty data, including at least one annual + one monthly subscription, one credit account, debit accounts, income rows, and transactions straddling `last_met`.
- [ ] A `tests/golden_parity.rs` renders the fixture, verifies it, and asserts the six headers + totals are present and correct.
- [ ] The fixture's `last_met` is a fixed date (not `today`) so tests are deterministic across days.
- [ ] No real financial data, tokens, or account numbers are committed.

## Interface contract
The fixture path is discoverable via `env!("CARGO_MANIFEST_DIR")/tests/fixtures/finance.db`. Units 02/03/04 tests share it.

## Boundaries — do NOT touch
`data/` is gitignored; keep secrets out. Do not depend on network or SimpleFin in tests.

## Output
`tests/fixtures/` seed + generated DB + `tests/golden_parity.rs`.

## Verification
`cargo test` green; `git ls-files` shows no `data/` secrets.
